## What is the MCP Gateway?

The **Model Context Protocol (MCP)** is an open standard that lets AI clients (like Claude Desktop, Cursor, and VS Code) connect to external tools and data sources called **MCP servers**. When an AI assistant needs to query a database, call an API, or run a script, it does so through an MCP server.

The **MCP Gateway** sits in front of your MCP servers and acts as a centralized control plane. Instead of every client authenticating separately to every server, all traffic flows through the gateway — giving you a single place to enforce auth, manage access, and inspect every tool call.

<Note>
  The MCP Gateway is part of the Portkey AI Gateway. You can run it with the same `npx @portkey-ai/gateway` command you use for LLM routing.
</Note>

## How it works

Without the MCP Gateway, each MCP client connects directly to each MCP server. This means you need to configure credentials on every client, manage access server-by-server, and have no centralized view of what tools are being called.

With the MCP Gateway, clients connect to a single endpoint. The gateway authenticates the request, checks the access policy, forwards the tool call to the correct MCP server, logs the result, and returns the response to the client.

```
MCP Client  →  Portkey MCP Gateway  →  MCP Server A
                      ↓                 MCP Server B
              Auth + Access Control     MCP Server C
              Logging + Forwarding
```

## Compatible clients

The MCP Gateway works with any MCP-compatible client:

- **Claude Desktop** — Anthropic's desktop application
- **Cursor** — AI-powered code editor
- **VS Code** — with the Continue or Copilot extensions
- **Any MCP client** — the gateway speaks standard MCP over HTTP
